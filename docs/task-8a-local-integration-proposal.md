# Proposed local Task 8a rehearsal

Status: Sabine approved local Task 8a preparation on 16 October 2026. This adds a local integration rehearsal to the earlier Phase 8 preparation exceptions. It does not complete Task 8a or authorize customer integration or launch.

## Purpose

Connect the existing sample app components to one local consultation coordinator in an automated rehearsal. This would catch differences between the browser's sample state and the actual protected coordinator before spending on another live experiment. The current app creates browser-memory preview models in `src/web/app.tsx`; the protected transcript/notebook/HTTP coordinator is tested separately. Passing both sets independently does not prove that they share one current session in the app.

## Proposed scope

1. Define a typed view adapter for authoritative session snapshots, edits and lifecycle results. Map all seven shared fields explicitly. The coordinator owns epoch/revision and confirmations; the view does not silently create a second confirmed brief or treat an optimistic change as accepted.
2. Build an isolated test host bound only to loopback, using the existing original owner pair, actual disposable native/replay stores and simulated identity/transcript/draft/check services. Reuse the app's layout and components through explicit injected ports. Keep this test entry disconnected from the customer host and default app startup. No real account, provider credential or paid request is used.
3. Exercise the app's sample reference, illustrative draft, feedback, comparison, saved-look and shopping-list components against the same context version. Generated sample images stay in browser memory; only explicit synthetic descriptions/reference versions enter the rehearsal context. Sample semantic outcomes cannot mint real recommendation, speech or shopping permission. Real product actions stay disabled.
4. Connect correction, interruption, Clear, End, simulated sign-out and expiry to cancellation and view updates. Separate explicitly saved sample records from temporary session notes. A delayed transcript, candidate or response must not recreate cleared data, overwrite a later edit or publish against an old epoch.
5. Run the complete automated browser journey plus affected keyboard/focus/large-text checks and backend regressions. Use made-up data and original illustrative assets only. Report each incomplete live/device/source/persistence requirement separately.

## Evidence to produce

- The browser and coordinator show the same seven-field values, confirmation states, epoch and revision after admitted sample input and touch corrections.
- One current context reaches sample generation/checking; corrections cancel stale work before any sample result is shown as current.
- A confirmed sample owned reference survives three scripted feedback rounds, its cost remains excluded, and later frames/events do not replace it.
- Comparison and explicit sample save/reopen/list controls preserve their separate scopes; reopening does not restore discarded notebook or feedback history.
- Clear/End/sign-out/expiry and simulated transport loss remove temporary data and prevent late output. Permanent/uncertain native/replay evidence is not erased to pass a test.
- A second simultaneous consultation is refused and another synthetic customer's context is inaccessible.
- No unvalidated real card, audio, provider call, customer-host mount, server photo upload or real retailer action is enabled.

## Limits and honest interpretation

Automated logical-time scenarios do not prove a usable live consultation lifetime, representative phone latency or production clock mapping.

Existing provider, source, privacy, hosted recovery, actual accessibility and launch acceptance gates remain open. Task 8a stays unchecked until its full integrated acceptance is actually met.
